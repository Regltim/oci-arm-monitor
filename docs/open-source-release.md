# 开源发布检查清单

本项目的源码、文档和示例配置只能包含通用占位数据。真实 OCI 配置始终保留在部署服务器，不进入公开仓库。

## 1. 检查当前快照

运行：

```bash
bash scripts/check-public-release.sh
```

脚本检查 Git 已跟踪文件，以及未跟踪但未被忽略的发布候选文件中的：

- 私钥内容和敏感文件类型。
- 长格式真实 OCI OCID。
- 邮箱地址。
- macOS 个人用户目录。
- `.env`、数据库、IDE、浏览器测试和构建产物。

需要额外检查自己的用户名、域名或其他标识时，在项目根目录创建本机文件：

```text
.public-release-denylist
```

每行填写一个固定字符串。该文件已被 `.gitignore` 排除，不要提交。

## 2. 不要上传整个本机目录

本机目录可能包含已忽略的 `.env`、OCI config、私钥、SQLite 数据库、截图和构建产物。开源发布只能使用 Git 已跟踪文件生成快照，不要直接压缩整个工作目录。

检查被忽略的本机文件：

```bash
git status --ignored --short
```

## 3. 使用干净 Git 历史

旧提交的作者信息和历史文件内容不会因为当前文件被修改而消失。公开发布时推荐：

1. 保留现有开发仓库为私有仓库。
2. 从通过检查的当前快照导出 Git 已跟踪文件。
3. 在新的公开仓库创建单个初始提交。
4. 为公开仓库配置专用的 GitHub noreply 邮箱，不沿用私人邮箱。

不要把现有私有仓库直接切换为公开，也不要把带旧历史的分支推送到新的公开仓库。

## 4. 发布后复核

在公开仓库再次确认：

- 默认分支只有清理后的公开历史。
- GitHub 网页搜索不到真实 OCID、域名、邮箱或个人路径。
- Releases、Actions artifact、Issues 和 Wiki 没有上传本地配置。
- README 和部署文档中的仓库地址、域名、账号全部是公共项目地址或占位符。

如果公开仓库需要隐藏所有者账号，还需要使用独立组织或专用公开账号；源码清理无法隐藏 Git 托管平台显示的仓库所有者。
